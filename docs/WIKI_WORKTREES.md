# 위키 검색과 워크트리 스킬

## 위키
작업 대상 프로젝트의 `openwiki/`를 우선 검색한다. 프로젝트에서 `wiki/`를 사용한다면 해당 경로를 지정한다.
`vibeops-search-wiki`는 질문·대상 버전 정의 → INDEX 확인 → 제한된 검색 → 관련 문서 읽기 → 현재 소스와 대조 → 출처 있는 요약 순서로 동작한다. 초기에는 관련 문서 최대 3개만 읽고 필요할 때 범위를 확장한다.
요구사항이 불명확하거나 설계 근거가 없거나 낯선 API·반복 실패가 있을 때 호출한다. 연결된 외부 위키 도구도 사용할 수 있지만 MCP 서버·벡터 DB·인증은 새로 설치하지 않는다.

## 워크트리
`vibeops-manage-worktrees`는 상태 확인 → 기준 커밋 기록 → 고유 경로·브랜치 생성 → 담당 경로 배분 → 실제 diff·검사 결과 확인 → 순차 통합 → 통합 후 재검증 → 안전한 정리를 안내한다.
호스트가 Git 명령을 실행한다. 자동 실행 엔진이나 훅은 없다. 미커밋·미추적 파일이 있는 worktree는 강제 삭제하지 않는다.

## 개발
공통 skills/ 수정 후 `git diff --check`로 두 호스트 패키지를 갱신한다. 기존 단계별 역할은 필요한 경우 두 스킬을 사용한다. 별도 위키 연구 에이전트를 필수로 추가하지 않는다.
실제 호스트에서의 검색 품질·작업 수행률은 별도 평가해야 한다.
