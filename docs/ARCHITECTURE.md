# 플러그인 설계

## 전체 흐름
사용자 요청을 받은 호스트가 vibeops-orchestrate-sdlc 스킬을 읽고 현재 단계를 결정한다. 각 단계는 필요한 파일만 읽고 호스트의 편집·터미널 도구로 작업한다. 독립 작업은 네이티브 서브에이전트에 할당하고 결과를 통합한다. 테스트와 리뷰의 실제 결과를 기록하고 사용자에게 반환한다.

## 역할과 결과물
| 단계 | 결과물 |
|---|---|
| 요구사항 | artifacts/requirements.md: 요구사항 ID와 수용 조건 |
| 설계 | artifacts/design.md: 구조와 작업 의존성 |
| 개발 | 실제 소스 변경 |
| 테스트 | artifacts/test-report.md: 명령·종료 코드·결과 |
| 리뷰 | artifacts/review.md: 발견 사항과 근거 |
| 배포 | 요청된 경우 artifacts/deployment.md |

artifacts/sdlc-progress.md는 작업 인수인계 문서다. 재개할 때 Git과 소스를 대조한다. 자동 트랜잭션 저장소가 아니다.

## 구성요소 경계
스킬은 방법, 에이전트는 담당 범위, 훅은 이벤트 반응, MCP는 외부 도구 연결이다.
Claude agents는 호스트가 읽는 역할 정의다. Codex TOML은 프로젝트 설정으로 별도 설치하며 플러그인의 자동 발견을 가정하지 않는다.
리뷰 역할은 소스를 수정하지 않고 부모에게 결과를 전달한다. 부모가 리뷰 문서를 저장한다.
SessionStart는 진행 안내를 출력한다. 오케스트레이터는 새 작업 흐름을 시작할 때 공용 위키 SHA를 한 번 확인한다. 같은 작업을 재개하면 체크포인트를 읽고, 검색 워커에 같은 로컬 경로와 SHA를 전달한다. 검색은 원격 Git에 접근하지 않는다. 테스트 통과를 강제하거나 상태를 수집하지 않는다. 실행에 sh와 호스트의 훅 허용이 필요하다.

## 제거한 구성
Python 실행 엔진·CLI·provider subprocess·SQLite 상태와 결과 캐시·워크플로 실행기·pip 패키징·런타임 테스트와 예제를 제거했다. 별도 실행 모드는 없다.
워크트리 생성과 통합은 필요할 때 호스트의 Git 도구로 수행한다. 사용자 변경을 덮어쓰지 않는다.

## 속도와 정확성
단계별 지침 로딩, 범위 제한 검색, 짧은 인수인계, 독립 작업 병렬화로 불필요한 토큰과 대기를 줄인다. 병렬화는 총 토큰을 늘릴 수 있다.
서버 prefill 캐시·추론 속도·정밀 토큰 집계는 플러그인이 제어하지 않는다. 성능 개선 수치는 측정 전 주장하지 않는다.
전체 소요시간은 요청 접수부터 최종 응답까지 측정하고 모델 대기·도구 실행·반복 횟수를 가능한 호스트 로그로 구분한다.
